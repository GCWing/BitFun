## 五、实现要点

1. **下拉 7 项驱动源**：硬编码数组 → `SUBSCRIPTION_AUTH_OPTION_VALUES` 常量（`subscriptionAuthOptions.ts`），`AIModelConfig.tsx` 用 `.map()` 映射 i18n label。**漏同步坑（侦查1 点名）**由此消除——下拉项与常量单一事实源。
2. **authSelectValue 构建**：`buildAuthSelectValue(provider, plan)`（opencode 带 plan 后缀，codebuddy/qoder 走 `subscription:${provider}`）。
3. **onChange 解析**：`parseAuthSelectValue` 统一解析（api_key / subscription:provider[:plan]），codebuddy/qoder 走通用 `{ type: 'subscription', provider }` 分支（非 opencode 无需改 base_url/provider）。
4. **面板状态展示**：`buildSubscriptionAccountDescription` 抽取原 descriptionParts 内联逻辑（connected+account+expires_at / tokenValid / vaultUnavailable / reauthenticationRequired / notSignedIn 五态），登录/登出/取消按钮、loginPanel（userCode/authorizationUrl/deadline 倒计时）均 ALL 驱动已现成——Qoder 设备码流 userCode 展示走 `loginPanel.userCode` 通用渲染（:3353-3358），无需额外 provider 特判。
5. **provider 特判（OPENCODE :3203 模式）**：codebuddy/qoder 无 plan 分组 → `api_offerings` 为空（后端 build_account mod.rs:445 仅 Opencode 非空）→ 面板自动走「Import as model」单按钮路径（:3252 条件 `account.provider !== 'opencode' || !hasOpenCodeOfferings`）——已覆盖，无需改动。
6. **零硬编码 key**：前端仅 provider 常量字符串（'codebuddy'/'qoder'），无任何 api_key/token 字面量；凭据全程后端 OS 凭据库。
