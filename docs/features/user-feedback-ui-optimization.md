## 背景与需求描述

BitFun 桌面端目前缺少一个完整、可用、体验连贯的**应用内用户反馈界面**。用户在使用过程中遇到的问题、建议、异常无法在应用内闭环提交，也无从知道官方是否回复，导致：

- 问题只能去外部 Issue 跟踪系统（如 GitCode Issues）手动提交，与应用内上下文割裂，提交成本高；
- 反馈无法携带应用版本、运行环境等关联信息，定位困难；
- 官方回复无法回流到应用内，用户不知道自己的反馈被处理；
- 隐私同意未与反馈提交绑定，无法满足"提交反馈前需同意隐私协议"的合规要求；
- 不同平台（桌面 vs HarmonyOS）缺乏一致的反馈体验。

因此希望新增一个**应用内用户反馈界面**，让用户在应用内完成"提交反馈 → 收到官方回复 → 回复与确认已读"的完整闭环，作为外部 Issue 系统的补充（而非替代）。

## 期望行为

### 1. 入口与未读感知

- 在底部常驻操作区提供"反馈"入口；
- 当存在官方回复且用户尚未确认已读时，入口给出醒目的未读提示；
- 未读提示只对"可打开且有新回复"的会话计数，避免历史不可操作项误报；
- 反馈服务不可用时入口清晰灰显并给出原因，而非静默不可点。

### 2. 提交流程

- 提交表单包含：反馈分类、内容、是否附带关联信息（版本 / 运行环境）、隐私同意勾选；
- 草稿判定：分类 / 内容 / 关联信息 / 隐私勾选任一非空即视为有草稿；
- 有草稿时关闭、切换视图或切换会话需经丢弃确认；
- 提交中冻结关闭按钮、遮罩点击与临界退出（避免误关丢草稿）；
- 内容超长时给用户明确截断反馈，不静默丢字；
- 提交成功后只展示单一完成动作，不并列冗余外链按钮。

### 3. 错误与配额态

- 配额超限时仅当服务端返回的正倒计时 > 0 时展示倒计时与重试按钮，避免"0 秒重试"无效态；
- 倒计时基于绝对截止时间，跨组件实例稳定；
- 隐私同意保存失败时给出可恢复文案并阻止继续提交；
- 网络 / 未知错误给出可重试入口，重试不丢失已填草稿。

### 4. 收件箱与会话

- 收件箱列表展示会话摘要、最近回复、未读标记；
- 未读关注只对"可打开且有新回复"的项计数；
- 回复发送态冻结关闭与遮罩，与提交态语义一致；
- 已读确认与打开会话分离，避免打开即静默确认；
- 切换会话时有未发送回复草稿时走丢弃确认 / 待定退出流程。

### 5. 布局与响应式

- 宽布局阈值（约 840px）基于容器宽度观察触发，宽态用双列布局（左侧列表 + 右侧会话）；
- 对话框尺寸有上限（约 960×620）并随视口收窄，小屏切单列；
- 顶部留白始终避开宿主窗口控件区，无遮挡；
- 高 DPI / 极小尺寸下文案与按钮可读性保持，不截断不重叠。

### 6. 隐私与同意

- 未同意隐私协议时，反馈请求必须在用户完成"同意"后才发出；
- 内联同意区提供只读隐私声明入口，文案区分前缀 / 后缀；
- 同意态切换即时反馈到入口可用性；
- 用户可经帮助菜单撤回同意，撤回后反馈通道进入未同意态。

### 7. 可达性与国际化

- 完整键盘导航：Tab 顺序合理、焦点环可见、Esc 行为可预期（提交 / 回复发送态除外）；
- `feedback.*` 文案完整，走命名空间懒加载，无硬编码；
- 表单控件带无障碍标签，错误态对屏幕阅读器可读。

### 8. 平台一致性

- HarmonyOS 走本地能力后端提交（凭据经安全资产存储），其他平台可外链外部 Issue 系统；
- 两条路径在未读关注、草稿、错误态上的体验对齐，差异仅在提交后端；
- 反馈相关 Tauri command 的远程工作区策略声明为与工作区位置无关，远程控制场景下反馈通道仍可用。

## 非目标 / 范围外

- 不替换外部 Issue 跟踪系统，应用内反馈是其补充；
- 不在本提案内设计反馈后端协议、配额策略或凭据存储模型；
- 不在本提案内撰写隐私协议正文（正文由隐私 owner 维护），仅做同意门交互；
- 不做反馈数据的可视化分析仪表盘；
- 不覆盖 CLI/TUI 形态的反馈呈现；
- 不做反馈内容的 AI 自动分类或摘要。

## 建议的落地路径（基于现有分层）

依据仓库的分层与边界规则，用户反馈界面应落在：

1. **Web UI 组件 (`src/web-ui/src/app/components/`)** — 反馈对话框、收件箱视图、会话视图、隐私声明链接、底部常驻入口的主要实现落点；复用既有 component-library 与状态管理，不新造前端原语。
2. **Web UI 布局 (`src/web-ui/src/app/layout/`)** — 对话框挂载边界与临界退出确认。
3. **Web UI 适配层 (`src/web-ui/src/infrastructure/api/`)** — 反馈 API adapter、错误类型、内容长度 / 截断工具；UI 组件不得绕过 adapter 直调 Tauri 或浏览器 API。
4. **Web UI i18n (`src/web-ui/src/locales`)** — `feedback.*` 文案；shared terms 经 `src/shared/i18n/contract/locales.json` + `pnpm run i18n:generate`。
5. **Desktop API (`src/apps/desktop/src/api/`)** — 反馈相关 Tauri command（提交、列表、回复、确认已读、访问态），远程策略声明为与工作区位置无关。
6. **Services (`src/crates/services/services-integrations`)** — 反馈服务具体实现（HTTP 提交、列表、回复、配额），放在显式 feature 后，`default = []`。
7. **OHOS 凭据 (`src/apps/ohos/`)** — HarmonyOS 反馈凭据与能力 token 的安全资产存取。

### 分层与依赖边界要点

- 产品逻辑平台无关：反馈服务核心实现与 DTO 保持平台无关，Tauri command、HarmonyOS 凭据、Web UI 适配分别落在各自 owner 层；
- UI 组件不得直调 Tauri / 浏览器 API，必须走 adapter / infrastructure 层；
- 复用既有 component-library 与状态管理，不新造前端原语；
- 主题 / 颜色 token 改动走颜色审计，失败时通过复用 token、合并冗余值或加最小 owner contract 修复，不抬 baseline；
- i18n 文案进 `src/web-ui/src/locales`，shared terms 进 `src/shared/i18n/resources/shared`；
- 日志英文、无 emoji、结构化；
- 反馈相关 command 远程策略声明为与工作区位置无关，不引入对远程工作区路径的隐式依赖。

## 设计草案 / 参考示例

- **未读提示**：未读关注判定为"可打开且有新回复"，底部入口据此触发提示徽标。
- **草稿与退出守卫**：草稿 = 分类 / 内容 / 关联信息 / 隐私勾选任一非空；提交 / 回复发送态早期拦截关闭，关闭按钮与遮罩点击跟随该态。
- **配额倒计时**：基于绝对截止时间计算剩余秒数；仅当服务端正倒计时 > 0 时展示，避免 0 秒无效重试。
- **隐私同意门**：提交顺序为"准备 → 同意 → 提交"；隐私保存失败阻止继续提交；内联区提供只读隐私声明入口。
- **布局**：容器宽度观察触发宽 / 窄双态；宽态双列、窄态单列；尺寸有上限并随视口收窄；顶部留白避开窗口控件。
- **平台分流**：HarmonyOS 走本地能力后端提交；其他平台外链外部 Issue 系统；提交后完成态不与外链按钮并列。
- **交互参考**：常见工单系统的"提交 → 列表 → 会话 → 已读"闭环；邮件客户端的未读徽标与草稿守卫。
