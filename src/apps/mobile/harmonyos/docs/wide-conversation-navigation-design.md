  trailing 操作按钮共用同一 content gutter。不再为恢复按钮把消息区、Composer 和内部操作按钮
  整体向右平移；该旧补偿在双屏没有可用余量时为 0，只有三屏会达到 72vp，导致同一交互在两种

## 背景

HarmonyOS 手机在展开双屏、完整展开三屏或其他宽屏形态下，本地会话和远程会话使用了两套不同的左栏：

- 本地会话使用常驻的 `AppSidebar`。
- 远程会话使用独立的 `RemoteMasterPane`。
- 从远程会话返回本地会话时，需要先点击远程左栏左上角的菜单按钮，唤出全局侧边栏，再选择本地会话。

这使本地和远程两个平级的会话来源表现为不同层级的导航。问题不只是视觉不统一，也增加了双屏下的操作路径和认知成本。

本设计统一宽屏 master pane，并明确三屏继续沿用双屏的 master-detail 信息架构。现有折叠单屏和普通窄屏交互必须保持不变。

## 目标

1. 在宽屏左栏中统一本地和远程会话的导航框架。
2. 用固定的“本地 / Remote”来源选择器表达一级上下文，让具体会话只承担二级内容选择。
3. 本地与远程分别保留自己的会话数据、连接状态和特有操作。
4. 切换来源时保留双方最后的活动会话及输入状态。
5. 展开、折叠只改变布局，不改变当前路由或会话状态。
6. 不改变现有单屏侧边栏、连接 Sheet、页面头部和系统返回行为。
7. 三屏左侧第一屏继续承载 master pane，右侧两屏共同承载 detail pane。

## 非目标

- 不把本地会话和远程会话混合为一个无来源区分的列表。
- 不重写单屏 `AppShell` 或抽屉动画。
- 不改变远程连接、配对、鉴权或断线重连协议。
- 不因为切换会话来源而停止桌面端正在执行的任务。
- 第一阶段不调整 `RemoteCreate` 的页面结构。
- 宽度阈值对齐官方 md/lg（600 / 840）；合盖与悬停强制单屏（悬停走 FolderStack 上下分带）。展开后是否进入宽屏由宽度、纵向折痕和折叠状态决定，不使用 `deviceType`。
- 不因为三屏增加一个独立的第三会话栏、第二套会话列表或新的业务路由模式。文件预览可以占用第三窗格。
- 展开会话不改造成 `FoldSplitContainer` 外壳：该组件只有预设比例，无法对齐实测折痕像素。折叠屏展开继续用折痕几何；悬停用官方 `FolderStack`。

## 当前逻辑

### 响应式判定

`AppRootPresentation.isWideLayout()` 当前遵循以下逻辑：

```text
设备处于折叠状态                                      -> 单屏
设备处于帐篷悬停（HALF_FOLDED / 双轴都半折，且不是仍横屏宽窗） -> 单屏 + FolderStack（上显示 / 下操作）
设备单轴半折、另一轴展开，窗口仍是横屏宽窗            -> 宽屏 master-detail（左第一屏 master，右展开带 detail）
设备非折叠，宽视口（≥600vp 或 media query），有纵向折痕，且放得下两栏 -> 宽屏
设备非折叠，宽视口，折叠屏展开且折痕缺失              -> 宽屏，合成中线铰链
设备非折叠，宽视口，无折痕                            -> 宽屏（断点驱动，含平板）
其他                                                  -> 单屏
```

折叠与悬停优先于宽度和折痕。双折叠展开的一道折痕与三折叠的两道折痕使用同一套 master-detail，不新增第三会话栏。

本应用自己用折痕几何做 master-detail，不能把会话交给系统 `Navigation` 分栏或平行视界。`module.json5` 的 `easyGo` 必须把 `wideWindowMode` 与 `squareWindowMode`（三折 M 态 / 双折展开）设为 `original`。根 `Navigation` 保持 `NavigationMode.Stack`，只承担单屏路由。宽屏可见内容必须画在 `Navigation` 外面，按 `activeRoute` 渲染 `WideConversationHost`；否则即使用 Stack，HarmonyOS 6.1 仍可能把 `Navigation` 切成 1:1，会话锁在左半屏，右侧露出 `startWindow`。

### 路由分流

当前 `AppRootPresentation.RouteContent()` 大致为：

```text
ChatHome / GeneralChat + 宽屏 -> WideGeneralChatContent
RemoteHome + 宽屏             -> WideRemoteHomeContent
RemoteChat + 宽屏             -> WideRemoteChatContent
其他                           -> RouteSurfaceContent
```

其中单屏路径最终使用：

```text
RouteSurfaceContent(route, true, true)
```

该路径负责现有页面头部、侧边栏按钮和返回按钮，是本设计的不可变边界。

### 当前不一致

```text
宽屏本地：AppSidebar + 本地会话内容
宽屏远程：RemoteMasterPane + 远程会话内容
```

改造前，`RemoteMasterPane` 左上角菜单按钮调用 `openSidebar()`。因此远程到本地不是左栏内的平级切换，而是“打开另一层侧边栏，再选择本地内容”。改造后，该宽屏菜单入口被移除，本地和远程都只通过常驻来源选择器切换；单屏菜单入口不受影响。

### 当前三屏表现

当前代码只有单屏和宽屏两档，没有三屏专用分支。`WIDE_MASTER_PANE_WIDTH` 固定为 `344`，detail pane 使用 `layoutWeight(1)` 占据剩余宽度。

因此三屏完整展开时，现有结构会自然表现为：

```text
固定 344 的 master pane + 横跨其余两屏的 detail pane
```

该方向与本设计目标一致，但仍需处理左栏边界与第一道折痕对齐、第二道折痕位于详情内部时的控件安全区，以及会话内容过度横向拉伸的问题。

## 设计原则

### 1. 路由是会话来源的唯一事实

宽屏左栏当前模式直接从路由推导，不新增独立的 `wideActiveSource` 状态：

| 当前路由 | 宽屏会话来源 |
| --- | --- |
| `ChatHome` | 本地 |
| `GeneralChat` | 本地 |
| `RemoteHome` | 远程 |
| `RemoteChat` | 远程 |

这样可以避免路由、左栏选中态和右侧内容之间发生状态漂移。

### 2. 统一外壳，不混合领域状态

统一的内容包括：

- 左栏宽度、边界和背景。
- 位置、尺寸、选中态和反馈一致的来源分段选择器。
- 标题、搜索、列表行、选中态和底部操作的视觉节奏。
- 连接失败、空列表和加载状态所在的布局区域。

继续分别持有的内容包括：

- 本地置顶、最近、归档以及本地草稿。
- 远程设备、工作区、连接状态和远程会话分页。
- 本地与远程各自的活动会话和消息状态。

### 3. 来源切换是导航，不是生命周期销毁

切换来源时禁止调用以下行为：

- 断开远程连接。
- 清空本地或远程活动会话。
- 清空任何一侧草稿或附件。
- 停止桌面端正在运行的任务。
- 重置设备、工作区或账号状态。

手机侧只允许按现有生命周期规则暂停或恢复当前不可见远程会话的轮询。

### 4. 三屏是双屏的超宽形态

三屏不引入新的信息层级：

- 左侧第一屏继续显示双屏下的 master pane。
- 中间屏和右侧屏共同组成一个 detail pane。
- 本地/远程来源选择器、列表能力和路由语义与双屏完全一致。
- 双屏与三屏之间切换只重新计算几何，不改变当前来源或会话。

## 目标布局

```text
RouteContent(route)
├── 非宽屏
│   └── 原 RouteSurfaceContent，保持不变
│
├── 宽屏会话路由
│   └── WideConversationShell
│       ├── WideConversationMasterPane
│       │   ├── 固定的“本地 / Remote”来源选择器
│       │   ├── 本地模式：本地操作和会话列表
│       │   └── 远程模式：远程状态、操作和会话列表
│       └── DetailPane
│           ├── 本地会话内容
│           ├── 远程会话内容
│           └── 远程 Home 占位内容
│
└── 其他宽屏路由
    └── 维持现有 RouteSurfaceContent
```

建议将宽屏公共结构收敛为 `WideConversationShell` 或等价组件。单屏 `AppSidebar` 仍由 `AppShell` 管理，不应被新宽屏组件替代。

### 双屏几何

```text
┌────────────────────┬──────────────────────────────────┐
│ Master pane        │ Detail pane                      │
│ 来源选择器 + 会话列表 │ 当前会话或 Home 占位              │
└────────────────────┴──────────────────────────────────┘
```

### 三屏几何

```text
┌────────────────────┬──────────────────┬──────────────────┐
│ Master pane        │                                     │
│ 来源选择器 + 会话列表 │          Detail pane                │
│                    │       当前会话或 Home 占位            │
└────────────────────┴──────────────────┴──────────────────┘
```

三屏中间和右侧不是两个独立的 detail，也不分别承载不同功能。它们是同一个连续的 detail pane。

## 三屏几何与折痕

### 布局模式

业务布局仍然只需要两档：

```text
Compact      -> 现有单屏页面和抽屉
MasterDetail -> 双屏和三屏共同使用的 master-detail
```

可以为 `MasterDetail` 额外携带 `isExtraWide`、可用宽度和折痕区域等 presentation 几何信息，但不应新增 `TriplePane` 业务模式。

### Master pane 边界

通过 `display.getCurrentFoldCreaseRegion()` 读取 `creaseRects`，可以同时表达双屏的一道折痕和三屏的两道折痕。该调用必须使用与现有 `safeFoldStatus()` 相同的异常回退原则。

当前 `344` 宽度可以作为无折痕信息时的兜底值。能够获得有效纵向折痕时：

1. 双屏优先让 master/detail 分界与第一道折痕对齐。
2. 三屏同样让 master pane 占据第一屏，并与第一道折痕对齐。
3. 必须为折痕自身保留安全间距，避免列表行、来源选择器或点击热区跨越折痕。该占位使用页面底色，不把折痕宽度画成分隔条。
4. 折痕坐标为像素，ArkUI 布局宽度使用布局单位；进入布局策略前必须转换到同一坐标系。

折痕信息不可用、坐标不在当前应用内容区域内或转换失败时，继续使用当前固定 master 宽度和弹性 detail，不得阻断页面渲染。

### Detail pane

三屏 detail 的外层容器横跨中间和右侧两屏，但内部会话内容不应无约束拉伸：

- 页面头部和背景可以占满整个 detail pane。
- 消息阅读区、状态内容和 Composer 应设置合理最大宽度，并在 detail pane 内稳定对齐。
- 存在第二道折痕时，会话详情仍占据第一道折痕之后的整段剩余宽度（中间+右侧），不得只留在最宽的那一屏。
- 收起 master 后：双折和三折都把会话铺满整窗，恢复按钮位于会话 Header 左端，与右侧操作按钮对称。展开态三折 detail 仍从第一道折痕铺到右缘；只有收起左栏时才占用第一屏。
- 最大宽度不能按视口宽度缩放字体，只限制内容容器。
- 第二道折痕位于 detail 内部时，不因此再切出第三会话栏；关键点击控件随内容带一起落在剩余两屏内。
- 第一阶段不利用第二道折痕拆出文件、任务或其他辅助面板。

### 几何更新

在以下事件后重新计算几何：

- `onAreaChange` 返回新的应用内容宽度。
- `foldStatusChange` 返回新的折叠状态。
- 折叠状态变化后重新读取当前折痕区域。

几何更新只能影响 presentation。不得由此压入或替换路由、连接远程设备、清空活动会话或重置草稿。

## 左栏交互

### 固定的来源选择器

宽屏左栏在本地和远程状态下都显示同一个“本地 / Remote”分段选择器：

| 选中来源 | 选择器状态 | 下方内容 |
| --- | --- | --- |
| 本地 | `本地` 选中 | 本地操作和本地会话列表 |
| 远程 | `Remote` 选中 | 远程状态、操作和远程会话列表 |

来源选择器是一级上下文控件；具体会话行是当前来源内的二级内容选择。两者不得使用相同的列表行视觉或选中语义。选择当前已激活分段不重复导航，选择另一分段才执行无转场来源切换，不能播放页面切换动画。

选择器在加载、空列表和远程断开状态下仍然可用。它不使用返回箭头、Home 图标或菜单按钮，因为来源切换既不是历史返回，也不是需要二次操作的菜单命令。

### 宽屏全局侧边栏规则

宽屏会话路由已经常驻一个 master pane，不应再从该 master pane 或 detail header 打开 `AppShell` 的全局 drawer。否则远程 master 会被本地 `AppSidebar` 再覆盖一层，形成两个左栏和两套导航层级；本地宽屏则没有对等且合理的行为，因为其 master 本身就是 `AppSidebar`。

因此断点规则固定为：

- 折叠单屏和普通窄屏：本地 `GeneralChatHeader` 与远程 `RemoteHeader` 保留菜单按钮，继续打开全局侧边栏。
- 展开宽屏：本地和远程 master pane 均不显示全局侧边栏按钮；来源切换只使用固定的“本地 / Remote”选择器。
- 宽屏远程会话 detail 继续隐藏返回按钮，依靠常驻远程会话列表选择内容，不增加侧边栏入口。
- 从宽屏折叠为单屏后，同一路由重新进入既有单屏组件，菜单按钮自然恢复；布局变化本身不自动打开 drawer。

### 本地模式

保持现有本地能力：

- 使用显式宽屏 variant，将原 `Remote` 导航行替换为固定来源选择器。
- 搜索。
- 置顶会话。
- 最近会话。
- 归档展开与收起。
- 新建会话。
- 会话归档、导出和删除。
- 账号与设置入口。

如果实现需要扩展 `AppSidebar`，应使用显式的宽屏 variant，默认值必须继续采用现有单屏 drawer 行为。禁止让宽屏条件散落在单屏侧边栏的事件处理中。

### 远程模式

保持现有远程能力：

- 在远程标题区域与会话列表之间显示同一个来源选择器，并选中 `Remote`。
- 当前设备和连接状态。
- 点击设备打开工作区选择器，并在设备行显示当前工作区摘要。
- 从设备行选中工作区后进入该设备的 Remote Home，使右侧执行上下文与左侧选择保持一致。
- 设备下只投影当前运行和当前选中的活跃 Agent；历史会话搜索、分页和删除继续留在远程 Home。
- 从 Agent 标题旁的唯一入口，在当前工作区创建 Agent；尚未选择工作区时先打开选择器。
- 打开活跃 Agent。
- 连接、重连和远程设置。

未连接时，仅将远程内容区域替换为断开状态和连接操作。来源选择器必须继续显示。

这一层是手机端产品投影，不是 wire migration：传输、缓存和升级兼容仍使用 `RemoteSession` 与原命令
名。当前工作区选择器只列出桌面已返回的最近工作区；在远端机器上任意浏览目录仍是未实现能力，
不得静默回退为手机本地文件选择。

## 来源切换状态机

### 本地切换到远程

宽屏来源切换使用单独的 presentation action，不复用单屏 `enterCodeEntry()`：

```text
点击来源选择器的 `Remote`
├── 已存在可恢复的活动远程会话
│   └── 进入 RemoteChat，恢复消息并恢复需要的轮询
├── 已连接但没有活动远程会话
│   └── 进入 RemoteHome
└── 未连接
    └── 进入 RemoteHome 的断开状态，由左栏提供连接操作
```

宽屏下不应因为点击“远程”而自动打开单屏连接 Sheet。

### 远程切换到本地

```text
点击来源选择器的 `本地`
├── 暂停当前远程会话在手机侧的可见态轮询
├── 保持远程连接和远程活动会话状态
├── 清理来源切换产生的多余返回路径
└── 进入 ChatHome，恢复本地活动会话
```

切换回本地不应先打开全局侧边栏。

### 返回栈

来源切换不应不断向 `NavPathStack` 压入 `RemoteHome -> RemoteChat -> ChatHome` 等历史。应使用明确的来源切换导航语义，使切换后的系统返回行为仍符合当前 `AppRouteContract`。

普通的会话内导航继续使用现有规则：

- `GeneralChat` 返回本地 Home。
- `RemoteChat` 返回远程 Home。
- `RemoteHome` 的单屏系统返回行为不变。
- 根 `ChatHome` 的系统返回保持当前基线，不在本次宽屏改动中新增拦截；当前侧边栏打开时返回会退出 Ability。

## 折叠与展开

折叠和展开过程中不得修改当前路由。

### 单屏变宽屏

- `ChatHome` / `GeneralChat`：出现本地 master pane。
- `RemoteHome` / `RemoteChat`：出现远程 master pane。
- 当前会话、草稿、附件和滚动状态应尽可能保留。

### 宽屏变单屏

- 同一路由重新走现有 `RouteSurfaceContent`。
- 单屏页面头部和侧边栏按钮重新出现。
- 不自动打开侧边栏或 Sheet。
- 不因布局变化连接或断开远程服务。

### 双屏变三屏

- master pane 继续位于左侧第一屏。
- detail pane 从右侧一屏扩展到中间和右侧两屏。
- 当前来源选中态、会话列表选中态和右侧会话保持不变。
- 不出现新的第三栏，也不触发新的数据加载语义。

### 三屏变双屏

- detail pane 从两屏收回到右侧一屏。
- 内部最大宽度和折痕安全区重新计算。
- 当前路由、滚动状态、草稿、连接和活动会话保持不变。

## 单屏不可变边界

实现时必须保持以下路径的行为不变：

1. `AppShell` 的侧边栏动画、遮罩、连接 Sheet 和设置 Sheet。
2. `AppRootPresentation.SidebarContent()` 的现有调用链。
3. `AppSidebar` 默认 drawer 模式的布局和事件。
4. 单屏 `RemoteHomeView`、`RemoteChatHeader` 和 `GeneralChatHeader`。
5. `enterCodeEntry()` 的单屏连接判断与 Sheet 行为。
6. `AppRouteContract.backAction()` 的现有返回合同。
7. 折叠状态优先于宽度的布局判定。
8. 当前宽屏阈值及 media query 语义。

新增的宽屏 presentation action 只能由宽屏 master pane 调用，不应替换现有单屏 action。

## 建议实现边界

### Presentation

主要改动应限制在：

- `pages/components/AppRootPresentation.ets`
- 新增的宽屏 master pane 组件（如有）
- `AppSidebar.ets` 的显式宽屏 variant（仅在确有复用需要时）

`RouteContent()` 应保留清晰的非宽屏早期分支，避免单屏意外进入统一宽屏组件。

### Runtime

可以新增宽屏来源切换动作，但应复用既有的路由、草稿持久化和远程轮询能力。不要在 presentation 层直接操作连接器、轮询控制器或会话仓库。

### Contracts

来源到路由的选择若包含条件判断，应放在可测试的纯函数或现有路由合同附近。不要让 UI 组件自行拼接返回栈。

## 完成标准

只有同时满足以下条件才视为完成：

- 宽屏本地与远程使用统一的 master pane 框架。
- 宽屏本地与远程在同一位置复用“本地 / Remote”来源选择器。
- 宽屏远程可以通过来源选择器一步返回本地。
- 宽屏本地与远程均不会在常驻 master pane 之上再打开全局侧边栏，折叠单屏仍保留原菜单入口。
- 本地与远程会话状态可以往返恢复。
- 远程断开时不会困住用户。
- 折叠和展开不改变当前路由或连接状态。
- 三屏保持双屏 master-detail 结构，右侧两屏只承载一个连续 detail pane。
- 三屏会话正文宽度合理，关键点击控件避开折痕安全区。
- 单屏验收矩阵全部与改动前一致。
- 自动化测试、HarmonyOS 构建和真机手工验证均有记录。
